Chapter One

The Problem (That Doesn't Exist)

Photographs have sat in galleries for decades in total silence, holding the same pose, saying nothing. Nobody has ever asked how the appam feels about being photographed instead of eaten. Nobody has checked whether the Mona Lisa is tired. Nobody has considered that your plastic chair has four legs and still cannot walk out of the frame.

Worse: nobody has ever been roasted in fluent Malayalam by their own furniture. A gap in the human experience, frankly overdue.

Chapter Three

Ingredients for the Potion

No agent framework, no RAG, no 3D engine, no vector database. Twenty-one throwaway spike scripts and a great deal of stubbornness.

Cauldron Base

  • TypeScript 5.9 (strict), Node 22, Express 4.22
  • React 18.3 + Vite 6.4 on the front end
  • Web Audio API, AudioWorklet, hand-rolled SVG — no animation library
  • Redis for character cards and transcripts (optional, degrades gracefully)

Deliberately Left Out

  • No state manager, no UI kit
  • No RAG, no vector database, no agent framework
  • No 3D engine, no video generation
  • No lip-sync — this is audio-reactive puppetry, and proud of it

Chapter Five

The Pensieve

Three memories worth extracting. The full run lives in the demo video and one minute of npm run dev.

The landing screen resumes a session: "നിന്റെ ചിത്രം ഓർത്തുവെച്ചു" — it remembered your picture, so you're not back at square one after a reload.

Chapter Six

The Unbreakable Vow

The roasting has a boundary, and the character cannot be talked out of it.

Fair game

Talking to a photograph instead of doing something useful. Your questions. Your lighting. Your impatience.

Never a target

Body, appearance, caste, religion, region, family, gender, age, disability, money. Private individuals are never named or given an invented life story.

this rule lives inside the prompt, not the UI. easy to skip, harder to enforce — took longer than the jokes did.
Chapter Seven

Why the Real One Isn't Behind This Page

Read before assuming this is just a lazy static deploy.

  1. The model has a ceiling. Ten requests a minute, provider-side. One conversation is one session — a few visitors at once would exhaust it, and hosting only makes that ceiling reachable by strangers.
  2. There is no login. A public URL would sit an unauthenticated door in front of live API credentials. It needs a concurrency cap and per-IP limits first.
  3. Microphones need HTTPS. A plain LAN address won't grant mic access — no shortcut around real hosting or a tunnel.
  4. The key can't move to the browser. Voice Live has no short-lived-token exchange, so every credential stays on the Node server for the whole conversation. Shipping it to the client would hand a permanent secret to every visitor — which is also why this static page cannot secretly be the whole app.

So: this page explains it, the demo video shows it talking, and npm run dev has the real thing running locally in about a minute.
